# AI pre-fill cho Yêu cầu báo giá + Dự toán, kèm Quotation Templates
Specs-Contract: process-first-ready-v1

Nguồn: 7 LSX/báo giá khác nhau trong [docs/baogia](../../docs/baogia) (12 PDF; 5 file đuôi `(1)` trùng hệt, bỏ qua) → 5 template tủ: lò hơi, bật tắt motor, ổ cắm, ATS, phân phối đa tủ.
Tên thật trong code (khác đề bài): `materials` = `items`; "Yêu cầu báo giá" = `sales_requests`; `estimate_cabinets/items` = `sales_estimate_panels` / `sales_estimate_bom_lines`. Route thật có tiền tố `sales/` (`estimate.controller.ts:64`).

## Scope decision (GATE-SCOPE — 2026-11-22)
- Existing: request + attachments `backend/src/plugins/sales/request/entities/request.entity.ts`, `request-attachment.entity.ts` (≤20 file, 20MB, S3); estimate = revision → panel → BOM/cost lines `backend/src/plugins/sales/estimate/entities/`; write gate `estimate.service.ts:62-65,466-481` (engineer được giao, engineeringLead, director; `assertWritable` đang `private`); create advances `assigned → estimating` `estimate.service.ts:225-292`; sửa nháp chỉ khi request `estimating|estimated` `estimate-edit.service.ts:202`; pricing step + engineer không thấy giá từ packet [director-and-price-access](../director-and-price-access/plan.md) D-06/D-07 (presenter chỉ bỏ khoá `estimate-price-visibility.util.ts:12-25`); BOM line copy `reference_price` `estimate-edit.service.ts:153`; Bull queue mẫu `backend/src/kernel/core/files/files.module.ts:20-25`; thông báo `notification.service.ts:129`; seed theo feature `sales.plugin.ts:12-21`; feature catalog BE/FE `sales.features.ts`.
- Not in repo: AI SDK/provider; parser Word/PDF đầu vào; bảng template; tầng "nhóm" trong dự toán; `@Cron` nào.
- Minimum change: template (data, API, UI, seed 5 mẫu) + `projects.quotation_template_id` tùy chọn + cột AI trên panel/BOM line + job AI bất đồng bộ tạo nháp dự toán + Review Mode/verify của kỹ sư. Luồng thủ công không đổi.
- Expansion signals: >8 file, 3 subsystem → một packet 12 task, vì mọi kết quả dùng chung cột AI và quyền ở task-01/06.
- User decision: KEEP; Q1–Q7 mặc định; Sales chỉ tạo dự toán qua nút AI.

## Out of scope
- Import template từ file lịch sử bằng AI; hỗ trợ Word; bộ đánh giá độ chính xác AI (EXPAND).
- Sales tạo dự toán trống thủ công; Sales sửa bản nháp; Sales gửi dự toán.
- Tầng "nhóm" trong dự toán; tự tạo vật tư mới; thay đổi pricing step đã có.
- Chặn "Gửi dự toán" khi còn dòng AI chưa verify.

## Acceptance criteria
| ID | EARS criterion | Proof |
|---|---|---|
| AC-01 | Where an estimate panel or BOM line is AI-created, the system shall store `is_ai_generated`, `ai_note`, `ai_confidence`, `is_verified` on it, keep them when a new revision is made, and `POST :id/verify` and `PATCH :id/bom-lines/:lineId/verify` shall set `is_verified` for an actor allowed `estimate:update`. | task-01 |
| AC-02 | When the AI client returns output, the system shall accept it only within the D-05 bounds and after `redactMoney`; malformed output shall fail the run with a typed error and no estimate row; no upstream body, header or key shall appear in the stored error or logs. | task-02 |
| AC-03 | When an actor holding `quotation_template:create` posts a template whose lines reference live items, the system shall create it; an unknown item shall return 400, a duplicate code 409, and deleting a template used by a project 409; `SEED_SCOPE=all` shall seed the 5 templates idempotently. | task-03, task-04, task-05 |
| AC-04 | When Sales, salesManager or director triggers `POST /sales/estimates/ai-prefill` for a visible request in `draft\|assigned` with no estimate (or a D-06 re-run) and at least one attachment or non-empty requirements, the system shall return 202 with a `runId`; two concurrent triggers shall yield one run and one 409; a request with an estimate, any other status, or a run past its daily cap shall be refused; an engineer or admin shall be refused; `GET …/:runId` shall return 404 for a run outside the actor's request scope. | task-06 |
| AC-05 | When the run succeeds, the system shall in one transaction re-check request status, estimate absence and item liveness, create the estimate, revision 1 `draft`, panels and lines, recalculate totals, apply D-10, advance an `assigned` request to `estimating`, and mark the run `succeeded`, then notify after commit; when it fails, or the request was cancelled or deleted during the run, the system shall write no estimate rows. | task-06 |
| AC-06 | While a revision is a draft, the system shall refuse every Sales edit of it and keep submit with engineer/lead/director; Sales shall price after submit as today. | task-06 |
| AC-07 | The system shall omit every money key from estimate responses for actors without `reference_price:read`, and shall not carry a money amount in AI-authored text visible to them (`ai_note`, activity, `technical_requirements`, run summary). | task-02, task-06 |
| AC-08 | When an AI draft exists and the request is assigned to an engineer, the system shall move the request to `estimating` in the same transaction as the assignment; a request without an estimate shall not change. | task-07 |
| AC-09 | When Sales opens an eligible request, the UI shall offer "Phân tích & Điền bằng AI", show run progress and result, and hide the button when ineligible or AI is not configured. | task-08 |
| AC-10 | When an engineer opens an AI-filled estimate, the UI shall highlight AI rows, show `ai_note`, offer verify per row and for all, warn about unverified AI rows on submit, and show no price. | task-09 |
| AC-11 | The estimate editor's manual flow (create, add panel/line, submit) shall keep passing its existing suites. | task-01, task-06, task-09 |
| AC-12 | When a project is created or edited with `quotationTemplateId`, the system shall accept an active template or null and reject the rest with 400, and the project form shall offer only active templates. | task-05, task-11 |
| AC-13 | The template UI shall list, create, edit, deactivate and delete templates with panels and lines. | task-10 |
| AC-14 | The full chain (template → project → request → AI → engineer verify and submit → Sales price) shall run on the real UI with the demo data kept. | task-12 |
| AC-15 | If a run stays `queued` or `running` past 10 minutes, or enqueueing fails, the system shall mark it `failed` and free the request for a new run; a stalled job shall not be retried. | task-06 |
| AC-16 | Where `AI_PROVIDER=openai` and `OPENAI_API_KEY` is set, the AI pre-fill shall call OpenAI through the same `AiClient` port with typed errors and no key or upstream body in logs; an unset key of the chosen provider shall give 503 `AI is not configured`; the compose file shall not blank a key defined in `backend/.env`. | task-13 |
